**RULES**

1.Configure a Network Request catalog item in the Service Catalog to capture request details such as request type, access level, device, and business justification.

2. As an Administrator, configure user groups for Network Team, Approvers, and Requesters, along with appropriate roles and access controls.

3. As a Developer, implement client-side logic to dynamically display fields based on the selected network request type.

4. Submit a network request through the Service Portal or Service Catalog.

5. The system validates request data and routes the request for approval based on network access type and priority.

6. Approvers receive automated email notifications to approve or reject the request.

7. Upon approval, the system automatically creates network fulfillment tasks and assigns them to the appropriate network team.

8. Network engineers process the task, update work notes, and complete the configuration or access change.

9. The request status is updated automatically as tasks progress (New, In Progress, Awaiting Approval, Completed).

10. Notifications are sent to the requester at key stages of the request lifecycle.

11. Administrators and Developers can track requests, approvals, task performance, and SLA compliance through lists, reports, and dashboards.
